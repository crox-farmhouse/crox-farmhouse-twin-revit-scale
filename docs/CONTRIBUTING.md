# Contributing

## Verify checklist

Run `npm run verify` before every commit. It runs the same steps as CI:

1. `npm run typecheck`: strict TypeScript for the app and the Node tooling
2. `npm run check:boundaries`: layer dependency rule (see [ARCHITECTURE.md](ARCHITECTURE.md))
3. `npm test`: Vitest unit tests (Node, no WebGL)
4. `npm run snapshot:check`: scene-graph fingerprint
5. `npm run lighting:check`: lighting consistency
6. `vite build`

For changes that affect asset URLs or routing, also check the GitHub Pages sub-path:
`VITE_BASE=/crox-farmhouse-twin/ npx vite build && VITE_BASE=/crox-farmhouse-twin/ npx vite preview`.

## Coding rules

- **No `any`.** Use precise types, unions, generics, or `unknown` with a type guard.
  Never silence errors with `as any` or `// @ts-ignore`.
- **Respect the layers.** UI code talks to the engine only through `TwinApi` (type-only import).
  `core` stays free of three.js and the DOM.
- **Asset URLs follow the base path:** write `` `${import.meta.env?.BASE_URL ?? '/'}textures/x.jpg` ``,
  never `'/textures/x.jpg'`. Optional chaining keeps the node-side tools (snapshot, lighting,
  USD export) working, since `import.meta.env` is undefined there.
- **Dev-only server features** (Vertex AI proxy, USD compile) live in `tools/dev-server/` as Vite
  plugins with `apply: 'serve'`. The production build must never depend on them, so the UI has
  to degrade gracefully when they are missing.
- **No secrets or project ids** in the repo. Read them from the environment
  (e.g. `GOOGLE_CLOUD_PROJECT`).
- Use inclusive naming, e.g. "placeholder", "stub" or "fake" instead of "dummy".
- Put unit tests next to the module as `*.test.ts`. Keep the logic under test pure: inject
  clocks and timers instead of using globals.

## Snapshot workflow

`tools/snapshot/` builds the whole scene headlessly (esbuild + recording-canvas stubs) and
fingerprints every object: name, transform, geometry, material, userData and interaction state.
It compares the result with `.snapshots/scene.snap`.

- **Refactors must keep the snapshot byte-identical.** `npm run snapshot:check` must print `OK`.
- **For intended scene changes:** run `npm run snapshot:check`, read the diff it reports, and
  confirm that only the objects you meant to change differ. Then run `npm run snapshot:update`
  and commit `.snapshots/scene.snap` together with the code change. Say in the commit message
  why the snapshot changed.
- `*.actual` files and the bundled `.snapshots/*.mjs` CLIs are git-ignored build outputs.

## Generated files

The OpenUSD stage under `usd/` (`*.usda`, `*.usdc`, `*.usdz`, `zones/`, `materials/`,
`lighting/`) is generated by `npm run usd:export` / `npm run usd:compile` and is git-ignored.
Only `usd/overrides/layout.usda`, `usd/README.md` and `usd/textures/**` are source files.
